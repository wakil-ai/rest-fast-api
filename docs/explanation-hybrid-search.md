# How Hybrid Vector Search Works

The WakilAI API retrieves legal documents using **hybrid search** — a combination of dense (embedding) and sparse (BM25 keyword) search over Milvus. This document explains what that means, why both matter, and how the `alpha` parameter controls the balance.

---

## The problem with vector search alone

Dense vector search finds semantically similar documents: "company dissolution" matches documents about "business liquidation" even though neither word appears in the other. This is powerful for paraphrased legal concepts.

But it fails when the user asks about specific identifiers:

- "Article 128 of the Labor Code" — the model may not rank documents containing exactly "Article 128" at the top, because many articles are semantically similar.
- "Case No. 3-12345/2023" — a case number has no semantic neighborhood; only exact keyword match works.
- Proper nouns, tax codes, regulation IDs.

Pure keyword search (BM25) handles these but misses paraphrases entirely.

Hybrid search gets both.

---

## How it works

Milvus stores two vector representations for each document chunk:

| Index | Type | What it captures |
|-------|------|-----------------|
| Dense (HNSW) | Float vector (dim=2560 for Qwen) | Semantic meaning |
| Sparse (BM25) | Sparse term-frequency vector | Keyword frequency |

At query time, both searches run in parallel and their scores are combined:

```
final_score = alpha × dense_score + (1 - alpha) × sparse_score
```

With `alpha=0.8` (the default):
- Dense (semantic) contributes 80% of the score.
- Sparse (BM25 keyword) contributes 20%.

The top-K documents by `final_score` are returned.

## Milvus implementation

**File:** [app/db/milvus_handler.py](../app/db/milvus_handler.py)

Milvus calls this **WeightedRanker hybrid search**:

```python
# Two search requests: one dense, one sparse
dense_request = AnnSearchRequest(
    data=[dense_vector],
    anns_field="dense",
    param={"metric_type": "IP"},
    limit=top_k,
    expr=filter_expr,
)
sparse_request = AnnSearchRequest(
    data=[query_text],  # BM25 tokenizes internally
    anns_field="sparse",
    param={"metric_type": "BM25"},
    limit=top_k,
    expr=filter_expr,
)

results = client.hybrid_search(
    collection_name=collection,
    reqs=[dense_request, sparse_request],
    ranker=WeightedRanker(alpha, 1 - alpha),
    limit=top_k,
)
```

The same Milvus filter expression (`filter_expr`) is applied to both searches, so metadata filtering (article number, source, date) applies before ranking.

## Embedding generation

Dense vectors are generated by the embedding provider selected via `EMBEDDING_MODEL`.

**Query embedding:**
```
query text → embedding API → 2560-dim float vector
```

**Document embedding (at index time):**
```
document chunk text → embedding API → 2560-dim float vector → stored in Milvus
```

The embedding model at query time **must match** the model used at index time. Changing `EMBEDDING_MODEL` without re-indexing will produce garbage scores — vectors from different models are not comparable.

### Supported providers

| `EMBEDDING_MODEL` | Model | Dimension | Location |
|------------------|-------|-----------|----------|
| `qwen` | Custom Qwen (vLLM) | 2560 | Local server |
| `novita_qwen` | `qwen/qwen3-embedding-8b` | 2560 | Novita API |
| `deepinfra` | `Qwen/Qwen3-Embedding-4B` | varies | DeepInfra API |
| `siliconflow` | `Qwen/Qwen3-Embedding-4B` | varies | SiliconFlow API |
| `openai` | `text-embedding-ada-002` | 1536 | OpenAI API |

> If you change the embedding model, update `EMBEDDING_DIM` to match and re-index all collections.

## Choosing alpha

`alpha=0.8` (default) works well for legal language, where concepts are often paraphrased but specific article references and code numbers must rank high. If you find:

- **Semantic matches are poor** (obvious paraphrases not surfacing): increase `alpha` toward 1.0.
- **Specific identifiers (article numbers, case IDs) are missed**: decrease `alpha` toward 0.5.

`alpha` is set globally in `config.py` (`ALPHA=0.8`) and per-assistant in the assistant's `RetrievalConfig`. Per-assistant values override the global.

## Trade-offs

**Dense-only (alpha=1.0):**
- Best for concept-level retrieval.
- Misses article number lookups, case IDs, proper nouns.
- Requires a high-quality embedding model.

**Sparse-only (alpha=0.0):**
- Best for keyword and identifier retrieval.
- Misses paraphrases and cross-language semantic matching.
- Degrades for short queries with no overlap to indexed terms.

**Hybrid (alpha=0.8, default):**
- Captures both — semantic understanding and keyword precision.
- Requires Milvus to store both vector types per document.
- Slightly higher query latency than single-mode search (two parallel ANN requests).
